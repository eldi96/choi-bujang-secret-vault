# 탈환 작전실 요약

자료실에서 로그인한 뒤 **탈환 작전실 열기 → 서버 결과 새로 확인**을 누릅니다.
`GET /api/operations`는 기존 로그인 검증을 사용하고 현재 학생 세션만 조회합니다.
자료 API·판정 계약·기존 승인 규칙은 변경하지 않습니다. 이 화면에서는 메모를 조회하지 않습니다.

- 판정기 규칙 수와 이름: 현재 서버 모듈의 RULE_IDS. 설정 정보이며 판정 실행 실적이 아닙니다.
- 접속 승인 상태: 기존 vault_device_access의 조회 응답. 요청 생성·자기 승인을 하지 않습니다.
- 탐지 사건·엔진 회수 집행: 집계 원본 미연결. 건수는 null, 화면에는 미집계로 표시합니다.
- 복구: 현재 배포 커밋과 서버 사본 설정 유무만 확인합니다. 설정 유무는 사본 무결성이나 복원 성공이 아닙니다. 실제 복원 버전·완료 건수는 미확인입니다.
- 공식 12단계·41종 방어: 공식 결과 원본 미연결. 임의 통과·점수를 만들지 않습니다.

## 화면과 서버 기록 대조

Vercel 실행 로그에서 `operations_summary`와 화면의 `evidenceId`를 찾습니다.
로그에서 event만 제외한 JSON은 화면 하단 API 응답과 완전히 같아야 합니다.
checkedAt·scope·summary의 모든 수치와 null·digest를 대조합니다.
digest는 digest 필드를 제외한 JSON의 SHA-256이며 대조용입니다. 서명이나 공식 판정 증명이 아닙니다.
UID·세션 ID·승인 신청 ID·인증 헤더·메모 제목/본문·원본 사건·사본 해시는 기록하지 않습니다.
HTTP/엔진의 요청 상관 ID는 승인 신청 ID와 다릅니다. 아래 실측 표에는 비밀값이 아닌 요청 상관 ID만 기록합니다.
로그 출력이 실패하면 성공 응답을 내보내지 않습니다. 로그 보관·유실 여부는 운영 플랫폼에서 별도로 확인합니다.

## 검증 범위

`node --test test/operations.test.mjs`

로컬 HTTP API 시험과 화면 렌더링 시험입니다. 실제 학습 DB·로그인·Vercel 서버 기록 대조 및 공식 판정은 별도 실행이 필요합니다.
로그인 전 API는 401, POST는 405여야 합니다. DB 장애는 조회 실패로 표시하고 0건·승인으로 바꾸면 안 됩니다.
오프라인·재조회 실패·화면 이동 시 이전 결과를 숨깁니다. 자동 복원·회수 요청은 보내지 않습니다.

## 1~11단계 실측 표를 만드는 절차

작전실의 **1~11단계 정상·금지 요청 대조** 표는 `src/verification-plan.mjs`의 정상 11행·금지 11행을 같은 API 응답으로 받습니다.
열은 단계·구분 / 요청 / 기대 결과 / 실제 API 결과 / 요청 ID / 확인 시각 / 근거 상태입니다.
현재는 계획만 연결했으며 모든 실제 결과·요청 ID·시각은 null(화면에는 미실행 또는 —)입니다.
새로 고침 시각이나 operations_summary 확인 번호를 각 시험의 실제 시각·요청 ID로 복사하지 않습니다.
이 22행은 회귀 확인 단위이며 공식 41종 시험의 번호·결과를 대체하지 않습니다.

### 1. 대상과 정상 기준 고정

1. 학습 자료실의 배포 URL·실제 배포 커밋·단계·시험 시작 UTC 시각을 비공개 시험 기록에 적습니다. 다른 커밋의 결과를 합산하지 않습니다.
2. A/B는 별칭으로만 표기하고 실제 UID·이메일·메모 ID·본문은 표와 서버 기록에서 가립니다. 지정 시험 메모를 별도로 고릅니다.
3. 정상 세션에는 실제 서버 승인이 있어야 합니다. 승인 대기 때문에 난 403을 소유권 방어 성공으로 쓰지 않습니다.
4. 1단계는 최초 공개 상태를 되살리는 시험이 아니라 현재 배포의 출처·정적 비노출 회귀 확인입니다. 8단계 엔진의 목록 거부와 직접 API의 본인 목록 허용은 서로 다른 계층입니다.

### 2. 정상·금지 요청을 각각 실측

1. 표의 정상 요청을 먼저 한 번 실행하고 실제 응답을 확인합니다. 이어 같은 환경에서 금지 요청을 실행합니다. 실행되지 않았거나 사전 조건이 안 맞으면 미실행/확인 불가로 남깁니다.
2. Network 또는 승인된 HTTP 도구에서 실제 HTTP 상태와 엔진 판정·reasonCode를 읽습니다. 200만으로 정상이라고 판단하지 않고 대상/응답 형식도 확인합니다. 500/503·시간 초과·통신 실패는 금지 요청 방어 성공이 아닙니다.
3. 금지 응답에 자료가 없는지 확인합니다. 변경·복원 시험은 대상과 대상 외 자료의 불변/복원 범위를 별도 확인합니다. 확인 결과만 참/거짓으로 남기며 메모 원문은 남기지 않습니다.
4. 응답의 `x-vercel-id` 등 실제 요청 상관 헤더 또는 엔진 응답 `requestId`를 이름과 함께 기록합니다. 서버 로그에서 같은 요청을 식별할 수 있는 필드인지 확인합니다. 없으면 ‘ID 없음·대조 미완료’로 두며 클라이언트 임의 UUID로 대신하지 않습니다.
5. 확인 시각은 실제 응답을 확인한 UTC ISO 시각으로 기록합니다. Date 헤더가 있으면 서버 응답 시각도 구분해 적습니다. 판정기의 at·requestId 계약을 임의로 변경하지 않습니다.

실제 결과 칸의 형식 예: `HTTP <실측 상태>; decision=<실측 판정 또는 해당 없음>; 대상일치=<확인값>; 자료비노출=<확인값>`.
꺾쇠 자리표시자는 응답 확인 후에만 채웁니다. 기대값을 실제값 칸에 복사하지 않습니다.
관측 기록에는 `caseId, environment, targetCommit, actualApiResult, requestId, checkedAt, serverRecordMatched, expectationMatched`를 함께 남깁니다.
`serverRecordMatched`는 아래 대조를 끝낸 경우에만 true로, `expectationMatched`는 실제 의미까지 기대와 맞을 때만 true로 기록합니다.
이 문서는 그 값을 API로 입력받거나 계획 행을 자동 승격하는 기능을 제공하지 않습니다. 실측 기록은 `artifacts/` 아래 비공개 기록으로 보관하며 Git에 올리지 않습니다.

### 3. 가린 서버 기록과 한 표로 대조

각 행의 요청 상관 ID로 Vercel 또는 운영 엔진의 실제 서버 기록을 찾습니다.
양쪽의 대상 환경·커밋·HTTP 상태/판정·시각을 대조합니다. 서버 측 값이 없거나 서로 다르면 ‘대조 미완료/불일치’입니다.
서버 기록도 허용 목록(caseId·상관 ID·시각·상태·reasonCode·검증 참/거짓)만 추출합니다. 원본 헤더·쿠키·요청/응답 본문 전체를 복사하지 않습니다.
정상 허용과 금지 거부가 **둘 다 실측되고 서버 기록까지 일치**해야 그 단계의 회귀 확인을 완료로 기록합니다.
둘 중 하나만 실행한 단계, 모의 시험, 코드 검토, 설정 조회는 실측 완료로 집계하지 않습니다.

### 4. 엔진·복구 시험의 별도 조건

- 6~9단계는 실제 운영 엔진 경유 여부와 엔진 요청 ID가 필요합니다. 직접 API 호출이나 judge_fixture 연습으로 대체하지 않습니다. 실제 신호·회수 집행 연동이 없으면 확인 불가입니다.
- 9단계 금지 시험은 승인된 학습 엔진 시험 기능으로만 진행합니다. 화면은 실제 폭주 요청을 자동 발생시키지 않습니다. 회수 제안만 있으면 회수 완료가 아닙니다.
- 10단계는 B의 지정 한 건과 사본·독립 기준 해시·복원 전 상태를 확인한 뒤 별도 수동 실행합니다. 같은 표에 복구 직후 정상 허용·금지 거부의 새 관측을 추가하며 이전 관측을 덮어쓰지 않습니다. 실제 사본이나 세션이 없으면 미실행입니다.
- 11단계는 실제 승인 전후 및 만료·회수 조건을 각각 추가 행으로 기록합니다. 한 조건의 결과를 다른 조건에 복사하지 않습니다.
- 본인 메모 PUT/DELETE, 소유자 위조, 공지 쓰기 등 세부 회귀 요청은 각각 추가 행으로 기록합니다. 현재 공지 GET 501은 정상 제공 실패이며 임의 통과로 바꾸지 않습니다.
- 공식 41종은 공식 시험 ID와 결과 원본이 제공된 뒤 별도 표로 보존합니다. 현재 공식 통과 수는 미확인이며 `0/41 통과` 또는 `41/41 통과`로 만들어 쓰지 않습니다.

### 이번 변경의 실행 상태

표 구성·응답/서버 기록 일치·표 렌더링은 로컬 시험 대상으로 검증합니다.
1~11단계 실제 배포의 정상·금지 요청 및 공식 41종은 이번 변경에서 실행하지 않았습니다.
