## 재현 방법

기존 폴더를 보존하고 새 빈 폴더를 선택한다. 아래 명령의 경로는 해당 PC에 맞게 바꾼다. GitHub에 올린 커밋은 공개 저장소를 `git clone <저장소 주소> <새 폴더>`로 받을 수 있다. 이번 준비에서는 로컬 원본을 대상으로 `git clone --no-hardlinks <원본 폴더> <새 폴더>`를 실행했다. 인증서·토큰·개인 설정은 임의로 복사하지 않는다.

별도 폴더에서 `git rev-parse HEAD`가 제출할 40자리 커밋과 일치하는지 확인한 뒤, `on-client`에서 [STUDENT_RUNBOOK.md](STUDENT_RUNBOOK.md)의 Node 확인, 실행, 브라우저 확인, 종료, 재실행을 따른다. 포트가 이미 사용 중이면 기존 프로세스를 유지하고 실행 도구의 `-Port`로 다른 포트를 고른다. 새 폴더에서는 별도의 계정·SDP 준비가 필요할 수 있으며 기존 폴더의 연결 성공을 이어받았다고 보지 않는다.

## 데이터 보존·복원 계획

기존 프로젝트와 Git 기록, 학생 데이터 및 별도로 관리되는 개인 설정은 삭제·초기화하지 않는다. 새 폴더는 원본과 분리하고 Git에 추적된 소스만 복제한다. `.env`, 개인 인증·설정, Git 밖 자료나 서버에 있는 보안 기록이 Git 복제만으로 백업된다고 가정하지 않는다.

학생 데이터의 위치와 백업·복원 권한을 먼저 담당자와 확인한다. 승인된 보관 위치에 필요한 데이터를 별도로 백업하고, 복원은 원본을 덮어쓰지 않는 별도 환경에서 담당자의 절차에 따라 검증한다. 비밀이나 실제 개인정보를 이 문서·Git·제출 묶음에 넣지 않는다. 실제 백업·복원 시험, 보관 대상과 서버 측 복구 가능 여부는 아직 확인하지 않았다.
